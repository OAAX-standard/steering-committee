## Notes

### 1. Presentation

Any feedback on any of the points mentioned in the presentation?

- **Status update (Ayoub):**
  - Mission: write an AI application once and run it on any hardware, making AI accessible and affordable for everyone.
  - OAAX 2.0 specification released at the end of October 2026.
  - Python bindings added on top of the existing C and C++ examples.
  - OAAX Manager downloads the right runtime for a server and verifies that the hardware is compatible. The conversion tool compiles and optimizes a model for a specific target.
  - Conformance suite (an installable package) is in progress. Vendors run it on their OAAX wrapper. Current checks are basic (functions exposed, naming, expected behavior); more precise checks will follow.
- **Supported hardware:** x86-64 and ARM CPUs on Linux and Windows; recent NVIDIA GPUs on all platforms; Intel CPUs, GPUs and NPUs via OpenVINO; Hailo H and HL chips; DEEPX chips.
- **In progress with vendors:** MemryX, SiMa.ai and Edge Cortex are being brought into compliance. MemryX and SIMA are open to a separate repository in the public OAAX GitHub. Edge Cortex is still discussing open-sourcing its SDK wrapper.
- **Feedback:**
  - Francesco has contacts at SiMa.ai (its product manager) and offered to push them toward compliance.
  - Francesco suggested reusing the detailed compliance checklist he built at Ultralytics for hardware partners (covering memory use during compilation, source distribution and package sizes) to make the conformance checks stricter.
  - Francesco noted that many hardware vendors have weak software, which is where OAAX can add value.
  - Ayoub described the software as stable, user-friendly and efficient; the main challenge is expanding the user base.

### 2. Exposing OAAX to the open-source community and potential users

Prompts: who to reach first (companies, developers, enthusiasts, other projects); which channels; who owns what. Builds on the 2026-10-06 notes (blog posts, social media, YouTube, conferences and webinars).

- Audiences and priority:
  - Hardware vendors: continue bringing SDKs into compliance (already in progress).
  - Developers and AI users: awareness of physical AI (AI running in the field) and of OAAX as the way to run one application on any hardware.
  - Model and training platforms, and AI application companies: Ayoub's "triangle" idea, with OAAX as the middleman between hardware, models and applications so that deployment becomes seamless.
  - Non-vision applications: Josef noted OAAX is not vision-specific, but the community around it is vision-focused. Reaching other AI application types would expose gaps in the interface.
- Channels:
  - Existing: OAAX website (blog under "Updates"), LinkedIn, Slack, X, and a YouTube channel with no videos yet.
  - Videos: Ayoub is considering AI-generated videos. Francesco suggested a technical tutorial or session with the four of us, possibly with Intel speakers.
  - Blog post: Francesco suggested writing one post on the website and reusing it for Reddit and LinkedIn.
  - Events and workshops: see Edge AI Foundation and ipXchange below.
- Open-source projects to approach:
  - Hugging Face: Ayoub wants to introduce OAAX and explore collaboration or sponsorship, including a seamless path from a Hugging Face model to the OAAX web API. Francesco knows people there and will reach out. DEEPX is building a similar Hugging Face-to-compiler flow.
  - Ultralytics: Francesco expects a yes for a workshop or blog post. Ayoub proposed collaborating on deploying models to hardware, since Ultralytics does similar work, to avoid duplicate effort. Josef wants to stay in the loop with them.

- Telemetry: Track usage of runtimes/toolchains. Keep it anonymous. Popular chips, downloads, etc.

  - Josef is not against it but thinks it is early. Install count and active-use count are the first and most basic metrics; deeper usage can come later. He also questioned whether the development effort is worth it at this stage.
  - Maxim noted that AI Manager (part of the Network Optix video management system) already runs on the OAAX runtime and reports usage statistics and license activations, so some data is already available.
  - Ayoub agreed it makes sense now, to see which actions have the most impact. Francesco will submit a PR; the set of metrics is to be decided in it.
  - Monitor activity after an event/change to know if we're doing well.
  - GitHub metrics.

### 4. Scope of `deploy-ultralytics` ([#8](https://github.com/OAAX-standard/steering-committee/issues/8))

Questions from the issue: which models besides YOLOv8 detection; which NPUs have priority; Python bindings or C API as the primary interface.

- Models and tasks: Not discussed. Question from the issue still open.
- Current state: the `deploy-ultralytics` repo is an example showing the same Ultralytics model running on different devices. Only CPU and Intel examples exist so far. Maxim wants more vendors and hardware.
- Target accelerators and order: Not agreed. Maxim asked which vendors the group wants first. The main constraint is CI: GitHub-hosted runners offer NVIDIA GPUs and Intel, so NVIDIA is the easiest to test, at about 15 cents per NVIDIA pipeline run (more tests means higher cost). Other vendors need a physical device in CI.
- Primary interface: Both C/C++ and Python.
- Technical partner to provide the hardware to use for CI: Needed. Francesco noted that CI needs a partner who provides access to a device from each vendor, so that someone can test right away. No partner identified yet.
- Request credits from AWS: Ayoub and Robin previously applied for AWS open-source sponsorship and were declined. Ayoub will re-apply with a stronger request to cover CPUs and NVIDIA GPUs (and possibly AMD). Maxim suggested Network Optix could also sponsor CI costs; Ayoub said the more sponsors, the better.
